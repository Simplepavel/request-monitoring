# Система заявок для общежития


## Роли

- Житель
- Исполнитель
- Админ
- Супер Админ

По умолчанию все пользователи имеют статус жителя.

Базовый принцип взаимодействия: житель оставляет заявку, указывает в ней общежитие и блок. Исполнители, которые прикреплены к данному общежитию, видят список всех связанных с этим общежитием заявок, отсортированных по приоритету.

## Житель

### Что может делать
- Создавать заявку
- Редактировать заявку
- Смотреть список своих заявок
- Регистрация/вход
- Редактирование профиля

### Регистрация жителя
Заполнить поля:
- ФИО
- Почта
- Телефон
- Пароль

### Вход жителя
Заполнить поля:
- Почта
- Пароль

### Создать заявку
Телефон, ФИО заявителя берём с БД.
Житель вводит свою общежитие и блок, затем выбирает, какой специалист ему нужен (сантехник, слесарь, токарь, электрик).
Дальше вводит описание проблемы (сломался туалет, не работает замок на дверной ручке).
По желанию прикладывает фото проблемы.

### Редактировать заявку
Разрешение редактировать заявку только при её отклонении исполнителем, после чего пользователь получает отказ и возможность повторно отправить заявку после редактирования. Сам пользователь по своему желанию ничего с заявкой после её размещения делать не может. После отклонения заявка редактируется и снова попадает в статус **Принято в работу**(В бд за заявкой закрепляется id исполнителя, который когда-то принял ее в работу).

### Смотреть список своих заявок
При переходе в раздел "мои заявки" житель видит все свои заявки и их статусы.

### Редактировать профиль
- Смена ФИО
- Смена телефона/почты (с подтверждением)

## Исполнитель

### Что может делать
- Видит список текущих заявок
- Вход
- Редактировать профиль

По умолчанию все исполнители регистрируются как обычные пользователи, позже специальный пользователь(админ) добавляет зарегистрированного жителя в исполнители. Житель, который хочет стать исполнителем, сообщает свой id админу, и тот уже добавляет его в таблицу "исполнители", заполняет все необходимые сведения(id общежития, position id и тд.)

### Видит список текущих заявок
Любую заявку можно охарактеризовать, как "с закреплением к исполнителю"
или как "ни за кем не закрепленную". По умолчанию все новые заявки не
закреплены ни за каким исполнителем. Список этих заявок, исполнитель
видит в главном меню и именно из них он может выбирать те заявки,
которые хотел бы выполнить.

В специальном разделе меню под названием "Активные заявки" буду уже те,
и только те заявки, которые закреплены за данным исполнителем.

### Вход
Всех исполнителей регистрирует админ. Вход происходит по почте и паролю, которая указывалась при входе.

По умолчанию пользователь находится в роли жителя, но он так же может перейти в статус 
исполнителя, если у него есть такая возможность.

### Редактировать профиль
- Смена ФИО
- Смена телефона, почты (с подтверждением)

После принятия в работу исполнитель обязан завершить начатую заявку.

## Админ

### Что может делать
- Вход
- Редактирование профиля
- Добавление исполнителей
- Удаление исполнителей
- Статистика по исполнителям (их список)
- Общая статистика по общежитию 

### Вход
Все админы регистрируется, как обычные жители. Позже специальный, уже назначенный пользователь(супер админ) добавляет зарегистрированного жителя в админы. Житель, который хочет стать админом, сообщает свой id супер админу, и тот уже добавляет его в таблицу "админы", заполняет все необходимые сведения(id общежития и тд.)

По умолчанию пользователь находится в роли жителя, но он так же может перейти в статус админа, если у него есть такая возможность.


### Добавить исполнителя
Ввести:
- id жителя, которого добавляем в исполнители
- Должность
- Закреплённую общежитие 

### Редактировать профиль
- Смена ФИО
- Смена почты, телефона (с подтверждением)

### Удаление исполнителя
- установить поле is_active в состояние false с указанием времени изменения(поле deactivated_at)
- Все заявки, которые он выполнил, остаются в БД.
- Все заявки, которые он принял в работу и не выполнил, переходят в статус «Ожидает рассмотрения».

### Статистика исполнителя
Админ видит число выполненных задач, ФИО, login, пароль и т.д. Число задач, ожидающих завершения.

## Супер Админ 

### Что может делать
- Вход
- Редактирование профиля
- Добавление админа
- Удаление админа
- Добавление супер админа
- Удаление супер админа
- Статистика по админам (их список)
- Статистика по супер админам (их список)


### Вход
Все Супер Админы регистрируется, как обычные жители. Позже разработчик добавляет некоторое опредленное количество Супер Админов. Житель, который хочет стать Супер Админом, сообщает свой id другому Супер Админу, и тот уже добавляет его в таблицу "Супер Админы", заполняет все необходимые сведения.

По умолчанию пользователь находится в роли жителя, но он так же может перейти в статус супер админа, если у него есть такая возможность.


### Редактирование профиля
- Смена ФИО
- Смена телефона/почты (с подтверждением)

### Добавление админа
Ввести:
- id жителя, которого добавляем в админы
- Закреплённую общежитие 

### Удаление админа
- установить поле is_active в состояние false с указанием времени изменения(поле deactivated_at)

### Добавление супер админа
- id жителя, которого добавляем в супер админы

### Удаление супер админа
- установить поле is_active в состояние false с указанием времени изменения(поле deactivated_at)


## Статусы заявок

- **Ожидает рассмотрения** — исполнитель ещё не увидел/не ознакомился с задачей.

- **Принято в работу** — исполнитель увидел задачу и ознакомился с ней, т.е. открыл 
описание, увидел номер блока, ФИО заказчика и т.д., и решил, что будет её выполнять.

- **Отклонено заказчиком** — заказчик не согласен, что работа выполнена до конца. 
Он оставляет комментарий, что не так и отклоняет заявку. Исполнитель, когда видит 
заявку с таким статусом, переходит в нее и ознакамливается с комментарием заказчика. 
После чего из статуса **Отклонено заказчиком** заявка снова попадает в статус 
**Принято в работу**.

- **Отклонено исполнителем** - исполнитель увидел задачу, ознакомился с ней, но решил, что это не его профиль, и отклонил её с комментарием, что не так с заявкой. 
Заказчик, когда видит заявку с таким статусом, переходит в нее и ознакамливается с
комментарием исполнителя. Далее редактирует ее и снова выставлает в общий доступ. Т.е.
заявка переходит в статус **Ожидает рассмотрения**.  

- **Ожидает подтверждения** — исполнитель увидел задачу, ознакомился с ней, связался с
заказчиком и выполнил её. Теперь надо дождаться подтверждения от заказчика.

- **Выполнено** — заказчик подтвердил, а исполнитель исполнил то, что от него требовалось

### Стек технологий

-Backend: Go (основной API), Python Flask (аналитика), C++ (вспомогательный сервис)
-БД: PostgreSQL
-Frontend: веб-клиент
-Контейнеризация и запуск: Docker

### Роль Python

У каждого админа есть возможность смотреть статистику
- Среднее время ожидания (время, которое проходит с 1-го статуса "Ожидает рассмотрения" до статуса "Выполнено" по всему общежитию, по отдельному блоку).
- Самая долгая заявка, которая еще не в статусе "Выполнено" и не в "Ожидает подтверждения".
- Количество полностью выполненных заявок (по всему общежитию, по отдельному блоку).
- Общее количество заявок.
- Самые частые проблемы (сантехника, электрика, плотницские работы).
- График по количеству обращений к сервису (по всем проблемам, по каждой в отдельности).
- Процент выполняемости (количество заявок в статусе "Выполнено" / общее количество заявок).

### Роль C++

Go в качестве клиента посылает запрос на C++, отправляет ему описание заявки по протоколу HTTP. 
C++ анализирует текст по ключевым словам и отправляет ему единственное число - приоритет заявки. 
Далее, пользуясь приоритетом, Go размешает заявку в нужное место в списке заявок исполнителя.
